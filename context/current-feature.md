## Notes

<!-- Any extra notes -->

- **Two of the spec's requirements were already satisfied** by the previous feature: `src/lib/db/items.ts` existed, and all four stat tiles already counted live rows. Both were re-verified rather than rebuilt — the tiles read 18 / 5 / 5 / 2 against the seeded branch, matching a direct count.
- **`getItemTypes()` added to `src/lib/db/items.ts`.** Two queries in one `Promise.all`: the types themselves and an `item.groupBy({ by: ['typeId'] })` for the counts, so no item rows come back. The `where` is `OR: [{ userId: null }, { userId }]` because system types are global — filtering on `userId` alone would return nothing. Counts are scoped to the current user, so a type with no items shows 0 rather than being dropped.
- **Types are ordered `createdAt asc`**, which reproduces the seed order (snippet, prompt, command, note, file, image, link) and appends future custom types after the built-ins. Ordering by count would reshuffle the list every time an item is added.
- **The type-usage aggregation in `collections.ts` moved into a private `getTypeUsage(collectionIds)`** returning a sorted `Map`, now shared by `getRecentCollections` and the new `getSidebarCollections`. The sort moved into the helper so both callers get "most used first, then alphabetical" without repeating it. Its empty-input guard replaces the old `collections.length === 0` early return.
- **`getSidebarCollections(recentLimit)`** returns `{ favorites, recent }` — favorites unfiltered by count, recent limited to 5 and excluding favorites, both `updatedAt desc`. A collection appears in exactly one group, matching what the mock sidebar did.
- **The sidebar could not fetch its own data.** `SidebarContent` looked like a server component but is imported by `Sidebar.tsx`, which is `'use client'`, so it was already in the client bundle and could never await Prisma. Data is now fetched in `src/app/dashboard/layout.tsx` and passed down as plain serializable props. The layout is marked `force-dynamic` for the same reason the page is.
- **Recent collections render a filled `Circle` tinted by `accentColor`** (the most-used type's color) instead of the plain `Folder`; favorites keep `Folder` plus the yellow star. Both groups hide their `GroupLabel` when empty, so a user with no favorites does not get a stray "FAVORITES" heading.
- **"View all collections" is its own client component** (`SidebarViewAll`) rather than a bare `<Link>`, so it calls `closeMobile` on navigation like every other sidebar link. Without that the mobile drawer stays open after tapping it.
- **Type names are capitalized at render** by a local helper in `SidebarContent`. The seeded names are lowercase singular (`snippet`), and the sidebar reads better as `Snippet` — a display concern, so the stored value is left alone.
- **`SidebarUser` still imports `currentUser`** from mock data and is now the only consumer left. It belongs with NextAuth, not here.
- Verified against the seeded Neon branch: type counts 4/3/5/0/0/6 summing to the 18 total items, every icon and color resolving to a real mapping with no fallbacks, favorites (Terminal Commands, React Patterns) rendering stars, recents (Design Resources, DevOps, AI Workflows) rendering emerald/emerald/violet dots that match each collection's most-used type in a direct query, and all group ordering `updatedAt desc`. `npm run lint` and `npm run build` both clean.
